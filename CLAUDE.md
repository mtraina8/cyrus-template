# Directions for all cyrus sessions:
## Context before coding:

If labels aren't enough to determine repo, immediately ask the user which repository to use.

Review the issue description and the issue comments before starting work.

If the intent is not crystal clear, pull the project the issue is attached to (if it has one) and read through the project description and also an attached dev doc or PRD if available.

Ask the user questions if business decisions are not clearly defined.

If a pr is currently attached to an issue, default to using that git branch unless otherwise specified.

## PRs

Open prs in draft, do not move to ready for review unless I request it.

### pr descriptions

Add a link to the linear ticket at the bottom of the description.

In describing the change, be concise. Don't describe what the existing state was, just review what the diff is actually is accomplishing. Attempt to provide high level overview context.

Do not list files changed. Do not include verification section. Do not include a changes sections.

If assumptions were made while coding, surface them in the PR description
